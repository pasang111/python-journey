                                                    Debugging

Debugging is the process of finding and fixing errors in code. It helps developers understand how their program works and identify problems.

A simple debugging technique is using print() with f-strings to check variable values and program flow.


def add(a, b):
    result = a + b
    print(f'Adding {a} and {b} gives {result}')
    return result

Here, print() helps check the values of a, b, and result to make sure the function works correctly.

NOTE: Difference in Debugging and errorhandling

Debugging = Why did this error happen? → Find and fix the cause.
Error handling = What should I do if this error happens? → Handle it properly.


                                    Interactive debugging with the pdb module

            Pdb
            pdb is Python’s built-in debugger. It lets you pause a program, inspect variables, and execute code step by step.

Python has a built-in pdb module that helps you debug your code step by step.

for eg:

import pdb

def divide(a, b):
    pdb.set_trace()
    return a / b

print(divide(10, 2))

* pdb.set_trace() → pauses the program at that line.
* You can then check variables, run code step by step, and see what is happening.
* This helps you understand why your code isn't working.

note : pdb is a debugging tool, not error handling.

Python’s debugger, called pdb. A debugger helps you pause your program and inspect what is happening.

1. What does set_trace() do?
Suppose code looks like this:

def divide(a, b):
    import pdb
    pdb.set_trace()
    return a / b

print(divide(10, 2))

Normally, Python would just run the code and give you:

5.0

But pdb.set_trace() tells Python:

"STOP HERE! I want to check what's happening in the program."

So Python pauses at that line.

this is the output from Python's debugger, pdb:

> /Users/fcc/Desktop/debugging.py(5)divide()
-> return a / b
(Pdb)

1. > /Users/fcc/Desktop/debugging.py(5)divide()
This tells you:

/Users/fcc/Desktop/debugging.py → the Python file you're currently debugging.

(5) → you're currently stopped at line 5.

divide() → the function you're currently inside.


2. -> return a / b
This shows the exact line of code where the debugger is paused:

return a / b

The -> means:

"This is the next line Python is about to execute."

For example, if your program is:

def divide(a, b):
    return a / b

and you use pdb, Python can pause before executing return a / b.


3. (Pdb)
This is the important part.

(Pdb)

means:

Python is waiting for you to enter a debugger command.

You're no longer simply running your program. You can inspect what's happening.

For example, you can type:

(Pdb) p a

to print the value of a.

Or:

(Pdb) p b

to print b.

If you had:

divide(10, 2)

you might see:

(Pdb) p a
10
(Pdb) p b
2

You can then continue executing the program with:

(Pdb) c

where c means continue.


What does the help sentence mean?
Your text says:

"If you enter help into the prompt, you'll see a list of commands you can use"

Because you're at:

(Pdb)

you can type:

(Pdb) help

and pdb will show you available debugger commands.

Some of the most useful ones are:
Command	        Meaning
p variable	    Print a variable's value
pp variable	    Pretty-print a value
n	            Execute the next line
s	            Step into a function
c	            Continue running
l	            Show nearby source code
q	            Quit the debugger
h	            Show help

breakpoint() - built-in function that starts a debugging session
